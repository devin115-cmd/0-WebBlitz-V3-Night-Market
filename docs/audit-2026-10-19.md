# WebBlitz Night Market — full site audit

**Date:** 19 October 2026
**Commit audited:** `d3b628e` (main, after the copy PRs #1 and #2)
**Scope:** build and test health, performance, accessibility, SEO and sharing, links and content, internationalisation, security, code quality and repository process.

## Summary

The site is in good shape overall. It's a small, readable Astro codebase (about 3,300 lines including the three message catalogues). It works without JavaScript, respects reduced motion, keeps its JS and CSS inside budget, and automated accessibility scans find no colour-contrast problems. Lighthouse gives 98 for accessibility and 100 for both best practices and SEO.

Four problems matter most before launch:

1. **Legal links are broken for English and Tamil visitors.** The footer, pricing and FAQ links point to `https://serendib.tech/en/terms/`, `/en/privacy/`, `/ta/terms/` and `/ta/privacy/`, and all four return **404**. Only the Sinhala (unprefixed) `/terms/` and `/privacy/` work.
2. **`npm run verify` is red.** The WebKit run of "hero headline finishes its entrance" fails 7 times out of 7 on a GPU-less machine. The cause is rendering cost, not a logic bug (see P2). There's also no CI, so nothing runs `verify` on pull requests.
3. **Decorative effects are very expensive without a GPU.** With software rendering, the home page manages about 11 fps in Chromium and under 2 fps in WebKit. The WebGL aurora alone produces 132 long tasks in 10 seconds under 4× CPU throttling. Lighthouse mobile performance is **56 (Sinhala home)** and **65 (English home)**.
4. **Copy points to pages that don't exist.** The FAQ tells visitors to "use the content checklist", but this site has no checklist page. A quarter of the message catalogue (77 of 327 keys) is unused V2 copy that still gets translated and reviewed.

### How it was measured

- `npm run verify` on Node 22.22.3. The WebKit test was then re-run 6 more times on its own.
- Lighthouse 12 (mobile preset: Moto G Power, 4× CPU, slow 4G) against `astro preview`, on `/`, `/en/` and `/en/designs/`.
- axe-core 4 through Playwright on `/`, `/en/`, `/ta/`, `/designs/`, `/en/designs/` and `/404.html`, after scrolling each page so reveals finish.
- Frame-rate probes in Playwright (rAF frames counted over 3 s), with layers turned off one at a time.
- `curl` against every external URL the site links to.

All lab numbers come from a cloud machine with **no GPU** (Chromium reports SwiftShader). Real phones have GPUs, so treat the absolute numbers as a worst case. The ranking of costs still applies on low-end devices, and needs a check on real hardware.

## P1 — Fix before launch

### 1. English and Tamil Terms and Privacy links return 404

`Footer.astro`, `Pricing.astro` and `Faq.astro` build legal URLs as `${legalBaseUrl}${localePath(locale, '/terms/')}`. For `en` and `ta` that gives a locale prefix that the legal site doesn't serve:

| URL | Status |
| --- | --- |
| https://serendib.tech/terms/ | 200 |
| https://serendib.tech/privacy/ | 200 |
| https://serendib.tech/en/terms/ | **404** |
| https://serendib.tech/en/privacy/ | **404** |
| https://serendib.tech/ta/terms/ | **404** |
| https://serendib.tech/ta/privacy/ | **404** |

So the "Read the full scope and terms" link in pricing, the FAQ link, and both footer links are broken for two of the three languages. The live terms page is titled "Terms · Serendib", so check that `LEGAL_BASE_URL` points at the WebBlitz application meant in the README.

**Fix:** either link every locale to the unprefixed pages, or get localised legal pages published. Then add an e2e test (or a build-time check) that requests every external legal URL.

### 2. `verify` fails on WebKit, and there is no CI

`tests/site.spec.ts:50` ("hero headline finishes its entrance and scroll effects run") fails on WebKit in every run (1/1 in `verify`, then 6/6 with `--repeat-each`). Five seconds after load, the heading words are still 40–99 px below their resting position, because GSAP gets only about 10 animation frames in that time.

This is not caused by the recent copy PRs, which changed only the JSON catalogues. It's a rendering-cost problem (next item): headless WebKit without a GPU drops to about 1.7 fps on the home page, so the 1.25 s entrance can't finish inside the test's 5 s budget.

There is also no `.github/workflows`, so `verify` only runs when someone remembers to run it.

**Fix:** reduce the compositing cost (item 3). That's the real fix, and the test will likely pass again. Then add a GitHub Actions workflow that runs `npm run verify` on pull requests, with `npx playwright install --with-deps chromium webkit`. Don't loosen the test to hide the problem.

### 3. Decorative layers are very expensive without GPU compositing

Frames drawn in 3 seconds on `/en/` at 1440×900 (a blank page draws about 180):

| Configuration | Chromium | WebKit |
| --- | --- | --- |
| Page as shipped | 34 | **5** |
| Grain, cursor glow, aurora and lanterns hidden; all `filter` and `backdrop-filter` removed | 181 | 50 |
| Plus hero CSS animations and marquee stopped | 181 | 168 |

The WebGL aurora on its own (Chromium, 4× throttle, 10 s): **132 long tasks and about 4.0 s of blocking time** with the aurora, against 3 long tasks and 0.34 s with WebGL disabled. That is why Lighthouse reports a total blocking time of about 130 s and time to interactive of about 175 s on both homes: the shader never lets the main thread go idle under software GL.

The main contributors are:

- the WebGL aurora (`src/scripts/aurora.ts`), running at up to 30 fps
- `.grain`: a fixed, full-viewport (`inset: -50%`) layer with `mix-blend-mode: overlay`
- the lanterns: 8 animated elements, each with `filter: blur() drop-shadow()`
- `backdrop-filter` on the nav, ghost buttons, chip, hero badge, motion toggle and filter bar
- large blurred halos (`.ticket__halo` uses `blur(40px)`, and the promise cards have blurred glows)

**Fixes, cheapest first:**

1. Create the WebGL context with `failIfMajorPerformanceCaveat: true`. Under SwiftShader this returns `null`, which was checked on this machine, and the existing CSS fallback then shows. This is a one-line change.
2. Skip the aurora, and possibly the lanterns, when `navigator.hardwareConcurrency <= 4` or `navigator.deviceMemory <= 4`. Or measure the first few frames and stop if they run past budget.
3. Bake the lantern blur and glow into a pre-blurred radial gradient instead of a live `filter`.
4. Give the grain a fixed size, or remove `mix-blend-mode` and lower the opacity of a pre-rendered texture.
5. Keep `backdrop-filter` on the sticky nav only, and use solid translucent backgrounds elsewhere.

Then recheck on a real low-end Android phone. The README already lists physical-device checks as not done.

### 4. Copy refers to a checklist page this site doesn't have

`faq.content.answer` ends with "Use the content checklist to prepare." in all three languages. V3 has no checklist page or link, so the sentence leads nowhere.

The catalogue also carries **77 unused keys** from V2: `checklist.*`, `detail.*`, `showcase.*`, `support.*`, `enquiry.*`, `availability.*`, `meta.detail|scope|checklist.*`, `footer.community|preferences|checklist`, and others. They cost translation and review effort; the last two copy PRs edited several of them. Because `check-i18n` treats every key as required, they can't be deleted without a deliberate decision.

**Fix:** either build a short checklist section (the `checklist.*` copy is ready and reviewed) and link it from the FAQ, or remove that sentence. Then prune the unused keys, or move them to an `archive` file. Also add an "unused key" warning to `check-i18n` (the key prefixes used with dynamic keys are `demo.`, `category.`, `faq.`, `catalogue.results.` and `offer.languages.extraTime.`).

## P2 — Should fix

### 5. Accessibility

axe and Lighthouse agree on two rule types. Neither is a blocker, but both are easy to fix.

- **Label in name (WCAG 2.5.3), 26 nodes on home and 82 on /designs/.**
  - On every demo card, the image link and the "Open demo" link get `aria-label="Open {demo} concept…"`, which doesn't contain the visible text "Open demo". Voice-control users who say "click Open demo" won't hit it.
  - The language links show "EN", "සිං" and "த" but are labelled "English", "සිංහල" and "தமிழ்".
  - The motion toggle shows "Pause motion" but has a longer label.
  - **Fix:** start each `aria-label` with the visible text ("Open demo: Kottu FM"), or use visually hidden text in place of `aria-label`.
- **Heading order.** On the home page, the three promise cards use `<h3>` straight after the `<h1>`. On /designs/, card titles are `<h3>` under the `<h1>` with no `<h2>`. **Fix:** use `<h2>` for the promise cards, and add a visually hidden `<h2>` such as "All designs" above the grid.
- **Duplicate tab stops.** Each card has two links to the same demo (the image and "Open demo") plus WhatsApp. That gives 148 focusable elements on /designs/. **Fix:** set `tabindex="-1"` and `aria-hidden="true"` on the image link, so keyboard users get one demo link per card.
- **Small targets on phones.** At 390 px, the footer links (Terms, Privacy, email, phone, designs, scope) are 20 px tall. WCAG 2.5.8 asks for 24 px unless spacing makes up for it. **Fix:** give `.footer li a` vertical padding so it reaches about 44 px.
- **New tabs aren't announced.** All WhatsApp and demo links use `target="_blank"` without telling the user. **Fix:** add a visually hidden "(opens in a new tab)" note through a shared component.
- **No `forced-colors` styles.** Glass buttons and chips rely on translucent backgrounds and box-shadows, which disappear in Windows High Contrast. **Fix:** add a small `@media (forced-colors: active)` block that gives buttons and chips real borders.
- **Not yet done:** a screen-reader pass (VoiceOver iOS, TalkBack) and a check of the filter-results live region in all three languages.

### 6. 404 page

- It's English-only, and its language switcher links to `/404/`, `/en/404/` and `/ta/404/`, which don't exist. Clicking a language on the error page leads to another error.
- **Fix:** hide the switcher on the 404 page, or point it at each locale's home. Ideally, show a short three-language message, because most visitors arrive from Sinhala links.

### 7. Social sharing and SEO

- **The per-locale share images aren't used.** `public/og-en.jpg`, `og-si.jpg` and `og-ta.jpg` (270 KB in total) ship in `dist/`, but `Base.astro` always uses `/og.jpg`. **Fix:** use `/og-${locale}.jpg`, and add `og:locale:alternate` for the other two locales.
- **No `robots.txt` or `sitemap.xml`.** Hreflang and canonical tags are correct, but a sitemap with `xhtml:link` alternates helps Sinhala and Tamil pages get indexed. `@astrojs/sitemap` does this in a few lines.
- **No structured data.** Adding `Organization` (or `ProfessionalService`) JSON-LD with the name, logo, phone, email and area served (`LK`) would let search results show contact details and the logo.
- **No `apple-touch-icon` or web manifest.** iOS home-screen bookmarks and Android share sheets fall back to a page screenshot.

### 8. Designs page loading

Lighthouse: LCP 2.8 s, CLS **0.079**, and an estimated 231–285 KB of image savings.

- **The LCP image is lazy-loaded.** The first card image (`mirror-day-1280.webp`) is the LCP element but has `loading="lazy"`. **Fix:** make the first 2–3 grid images `loading="eager"`, and give the first one `fetchpriority="high"`.
- **Layout shift.** The shift is on the card `<figure>`. The likely cause is the filter bar, which is `hidden` until JS runs and then appears above the grid. **Fix:** reserve its height (show it from the start but disabled, or give it a `min-height` under `.js`).
- **Oversized images.** `sizes` asks for 92vw on phones, so a DPR 2.6 phone downloads the 1280 px preview for a card about 360 px wide. **Fix:** add an 800 px or 960 px variant to the preview set, or tighten `sizes`.

### 9. Render-blocking CSS

The 10.7 KB stylesheet is external, because Astro's `inlineStylesheets: 'auto'` only inlines below 4 KB. Lighthouse estimates 0.7 s of savings on the English home and 1.8 s on the Sinhala home. **Fix:** set `build.inlineStylesheets: 'always'`. At 10.7 KB gzip across 7 pages this is a good trade, and HTML stays well under the 24 KB budget.

## P3 — Nice to have

### 10. Internationalisation and copy

- **"Total" is worded two ways in Sinhala.** `footer.enquiryNote` uses මුළු මිල, while other strings use මුළු මුදල. Pick one.
- **Native-speaker review is still open.** It's needed for the Sinhala and Tamil headlines from PRs #1 and #2. The rendered si and ta pages were never checked by a native reader.
- **Search ignores spelling variants.** It matches substrings of the localised and English names, but doesn't normalise Unicode, so Tamil and Sinhala input typed with a different vowel-sign order won't match. **Fix:** apply `normalize('NFC')` to both the query and the index.
- **Footer year.** `footer.copyright` uses the build-time year, so it goes stale until the next build. That's fine if the site is rebuilt at least once a year.

### 11. Security and hosting

- The site is static, with no forms, cookies or third-party scripts, so the attack surface is small. The JSON runtime island is escaped (`<` becomes `\u003c`), and external links use `rel="noopener"`.
- **No security headers are set in the repo.** There's no `_headers`, `vercel.json` or similar. **Fix:** on the host, set `Content-Security-Policy` (`default-src 'self'; img-src 'self' data:; script-src 'self' 'sha256-…'` for the inline bootstrap script; `frame-ancestors 'none'`), `Referrer-Policy: strict-origin-when-cross-origin`, `X-Content-Type-Options: nosniff` and `Permissions-Policy`. Also set long-lived `Cache-Control: immutable` for `/_astro/*` and `/previews/*`.
- **npm audit reports 3 high advisories** in `source-map-js` (GHSA-68fv-2mgg-jv7q), pulled in by Astro's build tooling. They aren't shipped to browsers. Upgrade through Astro rather than `npm audit fix`.

### 13. Code quality

The code is consistent, typed and easy to follow. Smaller points:

- `scripts/capture-previews.mjs` and `check-i18n.mjs` read `demos.ts` with regexes. That works, but it breaks silently if the formatting changes. Importing the module through `tsx`, or moving the demos to JSON, would be sturdier.
- `main.ts` (440 lines) holds every effect. It's still readable. If it grows, splitting out `hero`, `gallery` and `pointer` modules would keep the init order easy to follow.
- The demo previews still show the demos' former attribution, and six demos have no usable first screen (README). Recapture once the demo owner finishes rebranding.
- The README's provenance section says the copy was "copied unchanged" from V2 and mentions "Build Ready". Both are now out of date after PRs #1 and #2.

1. Fix the legal URLs (P1-1) and the checklist reference (P1-4). Both are small, user-visible fixes.
2. Add `failIfMajorPerformanceCaveat` and a low-end-device gate to the aurora, and cut live `filter`/`backdrop-filter` use (P1-3). Re-run `verify` to confirm WebKit is green.
3. Add a GitHub Actions workflow for `npm run verify` (P1-2).
4. Accessibility label and heading fixes, and a single tab stop per card (P2-5).
5. Per-locale share images, a sitemap, robots.txt and JSON-LD (P2-7). Fix the 404 page switcher (P2-6).
6. Designs page: eager first images, reserved filter-bar height, inlined CSS (P2-8, P2-9).
7. Host headers, dependency bumps, catalogue pruning and the README refresh (P3).
